# LifeOS 成长平台架构与推进记录

更新：2026-09-28。仅本地实施，无远端推送、外部账户写入或付费模型调用。

## 已实现的本地闭环

React 页面 → 本机 HTTP API → 串行应用服务 → 纯函数规则分析 → 独立成长记录 → 建议反馈 → Agent 证据交接与结果回传。

- `/analytics`：成长复盘；1/7/30 天窗口、事实、依据、建议反馈、历史、导出。
- `/metrics`：保留原详细统计。
- `/review`：保留日结、任务处置与更正历史，提供成长复盘入口。
- `/connections`：真实连接状态、规范化 Notion / Google 日历快照导入、冲突提示、Agent 解读导入。
- 程序执行：确认 MUST 口径、已结束投入、容量过载、重复延期、未日结缺口、日历重叠检测。
- Agent 交接：包含算法版本、时区、生成时间、原快照时间、证据 ID、用户反馈与相关外部快照；回传只允许观察和问题，不执行任务修改。
- 调度：本机服务每分钟检查，默认关闭。启用后在设定时间分析截至前一天的七天。服务重启后仅补最近一次到期作业。电脑关闭或服务停止时不运行。没有配置 Windows 开机启动或 Codex 定时任务。

## 数据所有权与兼容性

现有 V1–V5 导入兼容路径及 V5 任务备份保持不变。新增报告保存在任务数据目录的 `lifeos-growth.json`；每次写入保留 `lifeos-growth.json.previous.json`。成长记录不混入 `DailyReview`，也不会被旧任务导入清空。代价是任务备份和成长备份需要分别导出；界面已明确标注。

成长文件采用串行写队列、临时文件原子替换、版本和形状校验。反馈、调度和外部导入要求 revision 乐观锁。报告 ID 由源记录、外部快照、窗口、时区和算法版本生成，相同输入重复运行复用报告。

历史报告为生成时快照；用户更改源数据后需重新生成。完成数不是按期完成率，同一任务跨日确认按计划次数计；未记录不等于未执行。反馈“我已实践”仅为用户自报，不代表系统验证成效。没有自动打分或心理原因推断。

当前没有迁移 SQLite：第一阶段复用已有可靠备份结构，避免在同步契约未确定时迁移个人数据。需要长期大量记录、复杂查询、多进程写入时，再评估数据库迁移，迁移前完整备份并核对计数与引用。

## 本机应用发现与外部边界

本轮通过 Windows 启动菜单和进程信息确认 Notion 与 Notion Calendar 均已安装且运行。没有读取客户端凭据、Cookie、Token 或私有缓存。

Notion 官方的 Calendar 本地 API 用于定位并打开事件，不是读取全部任务和日程的接口。Notion 数据库项目可以显示在 Notion Calendar 中，但并不因此成为 Google 日历事件。两类源需分别接入并保留来源 ID。

- 官方依据：[Calendar connections & API](https://www.notion.com/help/notion-calendar-connections)
- 官方依据：[Use Notion Calendar with Notion](https://www.notion.com/en-us/help/use-notion-calendar-with-notion)
- 数据事务参考：[Dexie transaction](https://dexie.org/docs/Dexie/Dexie.transaction())

已发现可用的 Notion、Google Calendar 插件，用户本次选择不安装，因此本阶段不使用插件。桌面安装不能替代连接器授权。当前提供规范化快照导入和本机 API；以后通过用户选择的授权方式确定数据库、日历集合与字段映射，再做真实只读拉取验收。

用户已确定日历源为 Google；“扣栈的数据处理方案资料”具体指代仍待澄清。实现保持分析者中立，没有为未确认服务写入凭证或网络调用。

## 后续阶段与验收

1. 授权 Notion 与 Google Calendar 后，限定一个任务数据库和选定日历，只读拉取；验证分页、时区、重复事件、增量与删除语义。
2. 将连接器结果映射到已实现的外部快照 API。ID 必须使用包含数据库/日历 ID 的稳定命名空间。当前 upsert 不推断删除。
3. 根据用户确认的数据处理方案实现真实 Agent 执行器，记录实际分析者、输入版本、失败状态与资源预算。现在已经可以使用交接 JSON 进行人工触发的分析与回传。
4. 实现任务与时间段关联、用户确认的排期建议；不会把截止日期自动视为执行时间，不把日历经过视为任务完成。
5. 跨周比较建议采纳后的变化，区分自报与程序证据。最终才考虑有限外部回写。

## 验证策略

复用现有 Vitest 与 Node 测试。新增覆盖历史日期边界、跨午夜与去重、证据引用、报告幂等、并发 revision、Agent 无效依据、外部记录旧版本拒绝、持久化重启、调度补跑与损坏文件拒绝覆盖。

浏览器使用独立配置与合成数据，所有固定入口请求代理到隔离服务，避免修改个人数据。当前无 Browser 插件；现有 Playwright CLI 在 Windows 帮助退出时报 UV_HANDLE_CLOSING，浏览器验证改用其已安装的 Playwright 库，没有增加项目依赖。桌面 1504×1060、手机 390×844，检查成长、连接、今日、方向、日结及详细统计。
